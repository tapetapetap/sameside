# 같은편 4차 설계: 주행 영상 피드백 반영(두 지도, 대중교통 보이기, 영상 자막·전화 강조)

- 날짜: 2026-11-11
- 출처: 같은편 주행 영상에 대한 사용자 피드백(11/11). brainstorming에서 사용자가 화면 안(두 지도 나란히, 모든 카드에 두 지도)과 설계 세 부분(지도, 대중교통, 영상)을 직접 승인했다.
- 바탕: 1차(`specs/001-sameside-pickup`), 2차(`specs/002-arrive-and-continue`), 3차(`specs/003-group-pickup`). 저장소 6752608.

## 요청(피드백 요지)

1. 만날 곳 화면의 가로로 긴 지도 하나를 두 개로 나눈다. 하나는 만나는 사람들의 위치와 각자의 이동 경로, 다른 하나는 만나는 지점(차를 세울 곳)이다. 여러 명일 때 어떻게 띄울지 정한다.
2. 주행 중 차의 이동 동선이 내비에서 이어지지 않는다. 앱 문제인지 에뮬레이터 한계인지 묻는다.
3. 전화·마이크 표시가 작아서 켜진 때 눈에 띄지 않는다.
4. 영상 자막이 작다.
5. 어느 장면이든 만날 곳이 세븐일레븐으로 나온다. 대중교통 장면에서는 민지가 대중교통을 타야 한다는 내용이 화면에 보여야 한다.

## 현재 사실(탐색 결과)

- 만날 곳 카드(`Screens.kt` `spotCard`)에는 `SpotMap` 하나가 있다.
  - 높이: 1순위 230dp, 2·3순위 150dp
  - 범위: 짧은 변의 반이 140m이고, 지점이 가운데다.
  - 지도 밖 사람은 가장자리 화살표와 거리로만 보인다(대중교통이면 "민지 · 1호선").
  - 경로는 지도 안 사람의 초록 점선 직선뿐이다.
- 걷는 길 데이터는 없다. 걷는 시간은 직선 × 1.3으로 어림한다(`Pick.walk`).
- 대중교통은 시연용 1호선 한 구간이다.
  - 성균관대역 → 화서역, 1정거장, 기다림 4분, 탐 3분
  - 노선 모양은 없고 두 역의 위치만 있다(`TransitLeg.board`·`alight`).
- 한 명 픽업의 대중교통은 다음 순서로 진행된다.
  1. 안(`Offer`: 노선, 빨라지는 분, 지점)을 태울 사람 페이지에 보낸다.
  2. 받아들이면 지점이 안의 지점(화서역 약국 앞) 하나로 바뀐다.
  3. 차 화면에는 카드들 아래 작은 글 한 줄만 있다("민지님께 1호선 1정거장 안을 보냈어요" → "민지님이 1호선 타고 와요").
  4. 카드 줄은 "민지님 걸어서 3분 · 차 13분"이다. 여기서 3분은 내린 역에서 걷는 시간이다.
  5. 시연 `transit` 장면은 받아들이자마자 취소한다(40초 영상의 24초쯤).
- 함께 태우기 카드의 사람 줄은 "준호 1호선 12분"이다.
- 첫 글자 원 색은 이름 해시로 다섯 색 가운데 하나를 고른다(`Ui.kt` `AVATARS`). 시연 다섯 명은 겹치지 않는다: 민지 초록, 준호 주황, 서연 빨강, 할머니 보라, 도윤 파랑.
- 전화 표시(상단 가운데 초록 알약)와 마이크 점(오른쪽 위)은 Pleos 상태 표시줄이다. 앱은 이것을 고칠 수 없다.
- 주행(D) 중에는 Pleos가 같은편 화면을 가린다. 같은편이 운전 중 사용(DO)을 선언하지 않았기 때문이다(원칙 I). 그래서 주행 장면 영상에는 내비 화면이 나온다.
- 에뮬레이터 내비는 위치가 판교에 고정돼 geo fix를 따라가지 않는다. 앱 위치(FusedLocation)는 따라간다. 따라서 요청 2는 앱 문제가 아니라 에뮬레이터 한계다.
- 영상과 자막
  - 자막은 페이지가 VTT 트랙으로 얹는다(`::cue` 0.95rem). 전체 화면에서도 크기가 같다.
  - 이 컴퓨터의 ffmpeg에는 글자 그리기(drawtext·subtitles)가 없다. overlay·crop·drawbox는 있다. Python PIL 12.3이 있다.
  - 영상은 1280×720, 15fps다. 아래 72px은 Pleos 시스템 아이콘 줄이다.
- 앱 로그에는 "전화 걸기 요청", "통화 중 true", "통화 중 false", "기어 P 아님"이 남는다. 마이크 점은 통화가 이어질 때(통화 중 true 무렵) 켜진다.

## 결정

### D1. 만날 곳 카드: 모든 카드에 두 지도를 나란히 놓는다

- 고른 안(사용자 선택 A)
  - 카드 위쪽에 같은 높이의 지도 둘을 나란히 놓는다.
  - 왼쪽은 "사람과 이동 경로", 오른쪽은 "차 세울 곳"이다.
  - 높이는 1순위 230dp, 2·3순위 150dp로 지금과 같다.
- 버린 안
  - 위아래 두 지도: 카드가 길어져 2·3순위가 화면 밖으로 밀린다.
  - 큰 지도 + 확대 창: 확대 창이 사람 지도의 한 귀퉁이를 가린다.
  - 2·3순위는 지도 하나 또는 글만: 카드끼리 모양이 달라 비교가 어렵다.

### D2. 왼쪽 지도 "사람과 이동 경로"

- 범위
  - 빠지지 않은 모든 사람, 지점, 대중교통의 탈 역과 내릴 역이 모두 들어오게 자동으로 맞춘다.
  - 가장자리에는 여백을 둔다.
  - 최소 범위는 짧은 변 약 100m다. 지점 바로 앞에 있는 사람 때문에 지나치게 확대되지 않게 한다.
- 사람
  - 점, 이름, 경로를 첫 글자 원 색으로 그린다.
  - 한 픽업 안에서 색이 겹치면 뒷사람은 아직 쓰지 않은 색을 팔레트 순서대로 받는다. 왼쪽 목록의 원 색은 바꾸지 않는다.
- 걷기: 사람에서 지점까지 점선 직선이다. 걷는 길 데이터가 없으므로 방향만 보인다.
- 대중교통
  - 사람 → 탈 역: 점선
  - 탈 역 → 내릴 역: 노선 색 실선(1호선 남색, 다크 화면에서는 대비를 맞춘 밝은 색)
  - 내릴 역 → 지점: 점선
  - 역은 흰 네모에 노선 색 테두리를 두르고 역 이름을 쓴다. 실선 옆에 "1호선 1정거장"을 쓴다.
- 지점: 파란 핀과 "○○ 앞"
- 북쪽 표시, 축척(50m·100m·200m·500m·1km 가운데 지도 폭의 1/4쯤인 것), "© OpenStreetMap"
- 없애는 것
  - 가장자리 화살표와 거리: 모두 화면 안에 들어오므로 필요 없다.
  - 들어오는 방향 화살표: 오른쪽 지도로 옮긴다.
- 함께 태우기도 이 지도 하나에 모두 그린다.

### D3. 오른쪽 지도 "차 세울 곳"

- 범위와 축척
  - 지점이 가운데이고, 짧은 변의 반이 35m다(짧은 변 약 70m).
  - 축척은 20m다.
- 그리는 것
  - 길(실제 폭)과 지점 길 덧칠
  - 파란 "세울 자리" 띠: 지점 길가를 따라 진행 방향으로 약 18m
  - 들어오는 방향 화살표: 지점 뒤 30m에서 시작
  - 핀과 "여기 세워요"
  - 지점 이름
  - 기준 랜드마크: 범위 안일 때만
- 서 있을 곳
  - 들어오는 방향의 오른쪽 인도에 사람 색 점을 찍는다.
  - 오른쪽인 이유: 우측 통행이라 "같은 편" 길가는 늘 차의 오른쪽이다.

### D4. 지도 아래 글 줄

- 사람마다 경로 색 점을 앞에 붙인다.
  - 걷기: "민지 걸어서 3분"
  - 대중교통: "준호 1호선 1정거장(성균관대역 → 화서역) · 12분"
- 그 아래에는 지금 있는 줄을 그대로 둔다.
  - "차 n분"
  - 건너기·유턴 비교(한 명)
  - "근처로 데리러 가면 약 n분"(함께, 1순위)
- 한 명 픽업도 같은 모양(사람 줄 + 차 줄)이다. 지금의 "민지님 걸어서 3분 · 차 13분" 한 줄을 두 줄로 나눈다.

### D5. 대중교통이 보이게 한다(한 명 픽업)

- 안을 보낸 때
  - "만날 곳" 제목 바로 아래에 강조 카드를 둔다(연한 파랑 바탕, 파란 테두리, 열차 아이콘).
  - 문구: "민지님께 1호선 안을 보냈어요"
  - 설명: "성균관대역 → 화서역 1정거장 · 화서역 약국 앞에서 만나면 6분 빨라요"
  - 카드들 아래에 있던 작은 글 줄은 없앤다.
- 받아들인 뒤
  - 강조 카드 문구: "민지님이 1호선 타고 화서역으로 와요"
  - 설명: "성균관대역 → 화서역 1정거장"
  - 남는 카드(화서역 약국 앞)의 왼쪽 지도에 민지 경로를 그린다(점선 → 1호선 실선 → 점선).
  - 글 줄은 "민지 1호선 1정거장(성균관대역 → 화서역) · 14분"이다(분은 시연 위치 어림). 이 분은 걷기·기다림·탐·걷기를 합한 시간이다. 이 시간을 보이려고 안(`Offer`)에 도착 시간을 함께 둔다.
- 가는 중: 맨 아래 한 줄이던 문장을 맨 위의 같은 강조 카드로 옮긴다.
- 바꾸지 않는 것
  - 음성은 그대로다.
  - 함께 태우기에는 강조 카드를 넣지 않는다. 카드 줄과 지도에 1호선이 보이고, 음성 안내도 이미 있다.

### D6. 가는 중 지도와 태울 사람 페이지는 그대로 둔다

- 피드백은 만날 곳 화면에 대한 것이다.
- 가는 중 지도(`SpotMap`, 차 표시)는 지금 모양을 그대로 쓴다. 카드에서만 새 두 지도를 쓴다.

### D7. 영상: 자막을 영상에 입힌다

- 자막 그림 만들기(PIL)
  - 굵은 34px(720p 기준) 흰 글자를 쓴다.
  - 검은 띠가 아래 72px 시스템 아이콘 줄을 덮는다. 두 줄이 되면 띠가 위로 넓어진다.
  - 앞에 구분 칩을 붙인다: 음성(파랑), 전화(초록), 알림(호박), 함께(보라), 안내(회색).
  - 폰트에 그림 글자가 없어서 🔊📞🔔👥 대신 칩 글자를 쓴다.
- 만든 그림을 ffmpeg overlay로 시간에 맞춰 얹는다.
- 페이지의 VTT 트랙은 끈다(자막이 겹치므로). 영상 아래 "음성" 목록은 둔다.
- 버린 안
  - 페이지 `::cue`만 키우기: 전체 화면과 내려받은 영상에서는 여전히 작다.
  - 페이지 위에 HTML 자막 얹기: 전체 화면에서 사라진다.

### D8. 영상: 전화·마이크 순간을 강조한다

- 노란 테두리
  - 알약: "전화 걸기 요청"부터 "통화 중 false"까지(없으면 장면 끝까지)
  - 마이크 점: "통화 중 true"부터 "통화 중 false"까지
- 3배 확대 창
  - 전화를 건 순간에는 알약을, 통화가 이어진 순간에는 알약과 마이크 점을 3배로 키워 바로 아래에 4초 동안 띄운다.
  - 이름표는 "전화 연결", "마이크 켜짐"이다.
- 위치(1280×720 기준): 알약 x 508–612, 마이크 x 1132–1198, y 0–46. 장면마다 프레임으로 맞는지 확인한다.
- 앱 안에서 키우지 않는 이유
  - OS 표시라 앱이 바꿀 수 없다.
  - 주행 중 앱 화면을 띄우는 것은 원칙 I에 어긋난다.

### D9. 영상: 내비가 따라가지 않는 이유를 알린다

- 주행이 시작될 때(장면의 첫 "기어 P 아님") 한 번, 4초 동안 안내 자막을 띄운다: "에뮬레이터 내비는 판교에 고정돼 움직이지 않아요 · 앱은 GPS로 차 위치를 따라가요"
- 주행 영상 페이지 머리말에도 같은 뜻의 한 줄을 넣는다.

### D10. 시연 `transit` 장면을 길게 한다

1. 카드가 뜨면 6초 유지한다(세븐일레븐 카드와 "안을 보냈어요").
2. 민지가 받아들인다.
3. "타고 와요" 문구가 뜬 뒤 10초 유지한다.
4. 취소한다.

## 시연 장면과 영상

- 만날 곳 카드는 대부분의 장면에 나온다. 그래서 20장면을 모두 다시 녹화하고 자막과 강조를 입힌다.
- 같은편 주행 영상 페이지는 같은 주소로 갱신한다.
- 다른 두 앱(안 써본 기능, DRIVE DNA)의 영상은 이번 범위 밖이다.

## 범위 밖

- 인도를 따라 걷는 경로: 인도 데이터가 없어 점선 직선으로 둔다.
- 노선 모양: 두 역을 직선으로 잇는다.
- 앱이 전화·마이크 표시를 키우거나 주행 중 앱 화면을 띄우는 것
- 가는 중 지도와 태울 사람 페이지 변경
- 에뮬레이터 내비 위치 고치기
- 다른 두 앱 영상의 자막

## 검증 기준(초안)

- 단위 테스트
  - 범위 맞추기: 모든 점이 들어오고 최소 범위가 지켜진다.
  - 경로 구간: 걷기는 1구간, 대중교통은 3구간이다.
  - 겹친 색 다시 주기
  - 축척 고르기
  - 서 있을 곳이 들어오는 방향의 오른쪽인지
- 1·2·3차 단위 테스트가 그대로 통과한다.
- 화면 캡처
  - 만날 곳 카드: `opposite`(한 명 걷기), `transit` 받아들이기 전과 후, `group`, `group-transit`
  - 다크 화면 한 장
- 영상
  - 20장면 다시 녹화가 모두 통과한다.
  - 자막이 띠 안에 들어온다.
  - 전화 장면에서 테두리와 확대 창이 알약·마이크 점 위치와 맞는다.
