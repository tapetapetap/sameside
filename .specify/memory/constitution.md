# 같은편 Constitution

## Core Principles

### I. 운전 중에는 듣고 한 줄만 본다
주행 중(기어가 P가 아닐 때)에는 한 줄 카드 말고는 화면을 보게 하지 않는다. 알림은 음성 한 줄로, 한 번에 하나만 말한다. 지도·사진·긴 글은 태울 사람의 폰에만 보인다. 조작은 정차 중에만 받는다. 주행 중 화면은 움직이지 않는 한 줄 카드 하나(남은 시간과 다음 사람 상태)이고 누르기를 받지 않는다. (1.1.0: 6차 주행 중 한 줄 카드. 1.0.0은 "운전자가 화면을 보게 하지 않는다")

### II. 같은 편이 아니면 내지 않는다
픽업 지점은 차가 도착하는 쪽 길가(한국은 진행 방향 오른쪽)에서만 고른다. U턴이나 신호 건너편이 필요한 곳, 도로교통법이 정차를 금지한 곳은 후보에서 뺀다. 어느 편인지 확신할 수 없는 후보도 뺀다. 지점마다 고른 이유를 한 줄로 밝힌다.

### III. 위치는 픽업하는 동안만
태울 사람의 위치는 그 사람이 동의한 뒤에만 받는다. 탑승을 확인하거나 정해 둔 시간이 지나면 공유를 끝낸다. 이동 경로를 저장하지 않고, 계정을 만들지 않는다. 서버는 진행 중인 픽업의 현재 상태만 들고 있다.

### IV. 길 안내는 기본 내비에 맡긴다
앱은 지점을 고르고 알리기만 한다. 길 안내는 Pleos 기본 내비(NaviHelper)에 목적지·경유지로 넘긴다. 차나 에뮬레이터가 주지 않는 신호는 추측하지 않고, 확인한 신호만 쓴다.

### V. 최소 구현 (ponytail)
YAGNI → 표준 라이브러리 → 플랫폼 기능 → 이미 있는 의존성 → 한 줄 → 최소 구현 순서로 고른다. 쓰이지 않는 추상화, 설정, 확장 지점을 만들지 않는다.

### VI. 판단 로직은 테스트로 지킨다
지점 고르기, 같은 편 판정, 정차 금지 거리, 자동 전화 시점, 대중교통 이득, 탑승 판정은 안드로이드 없이 돌아가는 순수 코드로 둔다. 각각 실패하면 깨지는 테스트를 하나 이상 둔다.

## Constraints

- 플랫폼: Pleos Connect (AAOS, API 34 에뮬레이터), Kotlin, JDK 17, Android View
- 태울 사람 쪽은 앱 설치 없이 링크로 연다.
- 권한은 실제로 쓰는 것만 선언한다.
- 기준 수치(걷는 거리, 이득 기준, 전화 시점)는 검증 전 잠정값이며, 문서에 그렇게 적는다.

## Development Workflow

brainstorming(설계 문서) → /speckit-specify → /speckit-plan → /speckit-tasks → goldfish 리뷰 → 실사용 변화 제시(승인 게이트) → /speckit-implement(ponytail full) → ponytail-review → /code-review(서버와 위치를 다루므로 /security-review도).
