# 2-1 승인 게이트: 같은편 2차

- 날짜: 2026-11-10
- **승인 방식**: 사용자가 "내 승인 없이 끝까지 구현해둬"라고 지시했다(2026-11-10 새벽). 아래 실사용 변화와 결정을 사용자 대신 정하고 기록한 뒤 구현으로 넘어간다. 사용자가 아침에 바꾸고 싶으면 이 문서의 D번호로 말하면 된다.

## 실사용에서 달라지는 것 (예측)

### 운전자(차 화면·음성)

| 언제 | 지금(1차) | 2차 |
|---|---|---|
| 걸어서 딱 맞는 때(문턱) | "민지님께 전화 걸게요" + 곧 전화 | 아무 말 없음. 민지 폰에만 "지금 나오세요" 알림 |
| 문턱 + 60초 | — | 민지가 반응하지 않았으면 그때 "민지님께 전화 걸게요" + 전화. 반응했으면 아무 일 없음 |
| 150m 앞 | "오른쪽 세븐일레븐 앞이에요" | "오른쪽 올리브영 지나서 세븐일레븐 앞에 세우세요"(앞에 같은 길가 랜드마크가 있을 때) |
| 지점에서 오른쪽 깜빡이 켜고 3초 | — | "민지님께 도착했다고 알릴까요?" + P에서 보이는 카드 [보내기][아니요] |
| 지점 카드(정차 중) | 이름 · 이유 · 걸어서 n분 · 차 n분 | + 길을 건너야 하는 지점이면 "건너기 1분 · 유턴 m분" |
| 탑승 | "민지님이 탔어요" + 내비 안내 끝 | 원래 목적지가 있었으면 "민지님 탑승 확인. 다음 목적지로 안내할게요" + 경유지만 지우고 원래 목적지로 계속. 없었으면 그대로 |
| 지점 확인 | 내비 목적지가 지점으로 바뀜(원래 목적지 사라짐) | 원래 목적지가 있으면 그대로 두고 진입 경유지·지점을 경유지로 끼움 |
| 운전자가 내렸다 타기 | 문·좌석 조건이 맞으면 탑승으로 볼 수 있음 | 운전석 문은 탑승 판정에서 뺌 |

### 태울 사람(링크 화면)

- "지금 나오세요" 띠에 "지금 나가요" 버튼이 생긴다. 누르면 "운전자에게 나간다고 알렸어요"로 바뀌고 전화가 오지 않는다.
- 운전자가 보내기를 누르면 "차가 도착했어요. 세븐일레븐 앞으로 오세요"가 소리 2번과 함께 뜬다.
- 길을 건너야 하는 지점이면 "민지님이 길을 건너는 게 차가 유턴하는 것보다 k분 빨라요"가 보인다.
- 가는 중 화면에 "올리브영을 지나 세븐일레븐 앞 인도에 서 계세요"(또는 "세븐일레븐 앞 인도에 서 계세요")가 보인다.

### 잃는 것

- 문턱에서 바로 걸리던 전화가 60초 늦어진다(반응이 없을 때만 걸림). 민지가 알림을 못 보고 폰도 안 보면 차가 60초 더 가까이 온 뒤에야 전화가 간다.
- 원래 목적지가 이미 경유지를 가지고 있으면 1차처럼 원래 목적지를 잃는다(화면 한 줄로 알림).

### 예측할 수 없는 것

- 실차 내비가 경유지 방식으로 끼운 지점·진입 경유지를 어떻게 안내하는지: 에뮬레이터 내비는 자기 위치가 판교 고정이라 "경유지를 지나 원래 목적지로 이어 가는" 화면을 볼 수 없다. 탑승 뒤 내비의 목적지·경유지 값으로만 확인한다.

## 결정 (goldfish "사용자 판단" 항목, 위임 결정)

사용자 대신 정했다. 바꾸고 싶으면 번호로 말하면 된다.

| # | 질문 | 정한 것 | 이유 |
|---|---|---|---|
| D1 | 차가 반대 방향으로 들어와 건너편에 섰을 때 도착 알림을 보내면 어느 쪽으로 오라고 할까? (goldfish #3) | "차가 길 건너편에 도착했어요. 가까운 횡단보도로 건너 주세요" | 이미 떠 있는 crossOver 안내와 같은 방향을 가리키게 한다. 묻지 않는 안은 도착 알림의 쓸모를 버린다 |
| D2 | P에서 누르는 "보내기"도 "화면 조작 0번"에 세나? (#5) | 세지 않는다. SC-012는 P가 아닐 때의 조작만 세고 `opposite`·`handsfree`로 잰다 | 원칙 I은 주행 중 조작을 막는 것이고, P에서의 조작은 1차부터 허용했다 |
| D3 | 에뮬레이터에 남는 내비 목적지를 장면마다 어떻게 맞출까? (#6, #15) | reset이 앱을 멈추기 전에 "시연대기" 목적지를 넣고, 같은 이름을 navOwn으로 쓴다. 장면은 늘 reset 뒤에 돈다 | 장면 순서와 상관없이 일반 장면은 목적지 방식, continue 계열만 경유지 방식이 된다. 내비 상태를 읽어 맞추는 안은 앱이 멈춘 뒤 broadcast가 닿지 않을 수 있다 |
| D4 | 내비 답을 기다리는 동안 취소·끝·새 지점이 오면? (#16) | 요청마다 토큰, 대기 중 취소는 대기를 버림, 경유지를 다시 넣을 때는 REMOVE 콜백 또는 3초 뒤, 두 답이 모이면 바로 정함 | 1차의 pendingWaypoint 검사와 같은 생각을 경유지 방식에 넓힌 것이다. 끝난 픽업에 경유지를 넣는 일을 막는다 |
| D5 | 경유지 방식 취소(FR-035)와 경유지가 이미 있는 경우(FR-037)를 장면으로 볼까? (#17) | 본다. `continue-cancel`, `continue-full` 장면과 DemoReceiver `waypoint` 명령을 더한다 | 둘 다 내비 값으로 확인할 수 있고 스크립트가 짧다 |
| D6 | 옆길에서 꺾어 들어와 이미 기준 랜드마크를 지났으면? (#20) | 지나서 문장을 말하지 않고 1차 문장을 쓴다 | 지난 곳을 "지나서"라고 하면 틀린 안내다 |
| D7 | 태울 사람이 기준보다 앞(북쪽)에 있어 "지나" 문장이 빠지는 장면을 어떻게 보일까? (#21) | 규칙은 그대로 두고, "지나" 문장은 민지가 올리브영 남쪽에 있는 `arrive` 장면에서 보인다 | 반대 방향에서 오는 사람에게 "지나"를 붙이면 틀린 말이 된다. 데모 문장을 위해 규칙을 바꾸지 않는다 |

## 승인 뒤 구현 중 바뀐 것 (2026-11-10 새벽, 위임)

| 무엇 | 바뀐 것 | 왜 |
|---|---|---|
| 경유지 답이 3초 안에 안 올 때 | "경유지 없음" → **"경유지 있음"**으로 보고 목적지 방식(FR-037 한 줄이 보임) | 모르는 채 경유지 방식으로 가면 탑승 때 `removeWaypoint(ALL)`이 운전자의 경유지까지 지운다(코드 리뷰) |
| 픽업이 공유 끄기·만료로 끝날 때 | 앱이 넣은 내비도 지운다(1차는 탑승·취소 때만) | 경유지가 원래 길이나 다음 픽업에 남지 않게(코드 리뷰) |
| 도착 확인 질문 | 지점 길 위에서, 길과 나란히 섰을 때만 묻는다(반대 방향 도착은 묻는다) | 옆길 신호 대기에서 한 번뿐인 질문을 써 버리지 않게(코드 리뷰) |
| 알림 뒤 반응 | 대중교통을 받아들였으면 20m 이동을 반응으로 보지 않는다 | 차 안이라 늘 움직여 전화가 절대 안 가던 것(코드 리뷰) |
| 페이지 "k분 빨라요" | 차가 센 k(`fasterMin`)를 보낸다. 서버 필드 `crossing`·`uturnSec` 대신 | 규칙이 두 곳에 있지 않게, 건넌 뒤에는 줄이 내려가게(코드 리뷰) |
| 1차 건너편 띠 문구 | "가까운 횡단보도로 건너 주세요" → "건너편에서 기다려 주세요", crossOver면 건너편 경고 숨김 | 건너온 뒤에도 맞는 말, 반대 말을 하던 경고(1차 코드 리뷰) |
| 시연 `arrive` | P에 놓고 깜빡이를 끈 뒤 "보내기" | 깜빡이를 켜 두면 에뮬레이터의 측방 카메라 창이 버튼을 가린다 |
| 시연 `continue` 계열 | 확인 20초 뒤에 내비 상태를 읽는다 | 내비가 경유지마다 약 6초 경로를 다시 잡고 그사이 목적지가 빈 값이다 |

한계로 남긴 것: 내비가 경로를 다시 잡는 중 목적지가 빈 값으로 읽히는 때, 실내 위치 오차로 20m 이동을 잘못 보는 때(README 한계).
