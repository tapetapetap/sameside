## 리뷰

- ponytail-review(과설계): 내비 답 플래그 둘(`destGot`·`waypointsGot`)을 nullable 답으로 합치고, `Navi.DEST`를 없앴다(NONE과 같았다). 시연 `arrive`의 서버 조회를 한 번으로.
- /code-review(high) 10건 중 8건을 고쳤다.
  - 경유지 답이 3초 안에 안 오면 "경유지 있음"으로 보고 목적지 방식으로 간다(모르는 채 경유지 방식으로 가면 `removeWaypoint(ALL)`이 운전자의 경유지까지 지운다)
  - `going`에서 어떤 끝이든(공유 끄기·Gone·만료 포함) 앱이 넣은 내비를 지운다(경유지가 원래 길이나 다음 픽업에 남지 않게)
  - 대중교통을 받아들였으면 이동은 반응으로 보지 않는다(차 안이라 늘 움직인다)
  - 도착 확인은 지점 길 위에서, 길과 나란히 섰을 때만 묻는다(옆길 신호 대기에서 한 번뿐인 질문을 써 버리지 않게). 반대 방향 도착은 묻는다(D1)
  - 잃은 원래 목적지(`lostDest`)는 그 픽업 동안 남는다
  - 태울 사람이 길을 건넌 뒤에는 비교 줄이 내려간다(`crossing`을 다시 계산)
  - 페이지의 "k분 빨라요"는 차가 센 k(`fasterMin`)를 쓴다(규칙이 두 곳에 있지 않게)
  - "기준보다 차가 오는 쪽" 비교를 함수 하나로
  - 고치지 않고 한계로 둔 것: 내비가 경로를 다시 잡는 몇 초 동안 목적지가 빈 값으로 읽히는 경우, 실내 위치 오차로 20m 이동을 잘못 보는 경우(README 한계)
- 보안 점검: `/security-review`는 작업 디렉터리가 git 저장소가 아니라 돌지 않아 같은 관점으로 직접 봤다. 새 서버 필드(`ack`·`arrived`)는 타입을 검사하고, 페이지의 새 문장은 모두 `esc()`로 넣는다. 서비스 로그에 남던 링크 id(위치를 볼 수 있는 열쇠)와 전화번호를 뺐다.

## 구현 중 알게 된 것

- **오른쪽 깜빡이를 켜면 에뮬레이터가 측방 카메라 창을 띄워 화면 왼쪽을 가린다.** 도착 확인 카드의 "보내기" 탭이 그 창에 맞아 눌리지 않았다. 시연은 P에 놓고 깜빡이를 끈 뒤 누른다(quickstart 고침).
- **내비는 경유지를 하나 넣을 때마다 약 6초 경로를 다시 잡고, 그사이 목적지가 빈 값으로 읽힌다.** 시연의 상태 확인을 확인 20초 뒤로 늦췄다.
- **이 에뮬레이터 내비는 경유지 칸 번호를 무시하고 부른 순서대로 뒤에 붙인다**(research R15 보충). 경유지 방식에서 진입이 빠진 때가 한 번 있었다(경로를 다시 잡는 중에 둘째를 넣은 탓으로 보인다). 지점은 늘 남았다.
- 1차 코드 리뷰로 "동의 뒤 다시 열면 위치 보내기를 다시 켠다"를 넣은 뒤, 위치를 못 받으면 오류 화면이 만날 곳 안내를 가렸다. 만날 곳이 정해진 뒤에는 안내를 두고 띠로만 알리게 고쳤다(1차 contracts/ui.md).
