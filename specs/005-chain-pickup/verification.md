## 4. 리뷰

- **goldfish**: 지적 36개 중 30개 문서 수정(readiness 첫 실행 NO-GO → 재리뷰 GO), `goldfish-review.md`
- **ponytail-review(T019)**: 1건 반영. `ChainStrip`의 `hasDest` 인자는 구간 수로 알 수 있어 계산 값으로 바꿨다.
- **/code-review high(T020)**: 10건 가운데 7건 반영, 3건 유지.
  - 반영
    1. 다음 지점 사람이 먼저 와서 탔으면 그 지점을 건너뛴다(`nextStop`)
    2. 차례 모드에서 이미 탄 사람이 공유를 꺼도 빠짐으로 보지 않는다
    3. 탄 사람이나 지금 지점이 아닌 사람에게 건너편 띠를 보내지 않는다(`wrongSide`)
    4. 목적지는 확정 전에만 받고, 만날 곳에서는 목적지 구간만 다시 센다(카드 순서·만료를 건드리지 않는다)
    5. 계획이 있으면 일반 확정도 비교 줄을 지운다
    6. 확정 때 사람별 plan을 한도 없는 걷기 plan으로 만든다(고른 뒤 움직여도 null·대중교통이 되지 않게)
    7. 둘째 지점의 누적 좌석 규칙을 단위 테스트로 지킨다(에뮬레이터는 뒷좌석 착좌가 늘 앉음이라 시연으로 볼 수 없다)
  - 유지
    - 차례 분기를 한 모델로 합치기(모든 확정에서 `stop`을 채우기): 1~4차 경로(확정, 대중교통 받아들임)를 건드려 회귀 위험이 크다
    - 확정 뒤 `chain.stops`와 `p.spots`의 중복: 확정 전 카드가 `chain.stops`를 쓴다. 확정 뒤에는 `who`와 이름만 읽는다
    - `nearby`와 `chain`이 1순위를 각각 구하는 비용: 사람 3명·랜드마크 10개라 무시할 만하다. 두 값은 쓰임이 다르다(계획이 없을 때 비교 글)
- **보안 직접 점검(T021)**: 이 작업 폴더 밖에서는 /security-review가 돌지 않아 같은 관점으로 봤다.
  - 서버·페이지·매니페스트·디버그 소스셋·빌드 설정이 바뀌지 않았다. 새 권한도 없다.
  - 새로 저장하는 값이 없다(diff 추가 줄에 저장 API 0개).
  - 내비 원래 목적지 좌표(`destPos`)는 픽업 메모리에만 두고 서버로 보내지 않는다(`Relay`에 쓰는 곳 없음).
  - 다른 사람 페이지 값에 사람 위치는 없다. 지점 목록에는 랜드마크 좌표와 그 지점의 걷는 시간·서 있을 곳 문장이 들어간다(3차 함께 모이는 곳과 같은 범위).

## 5. 남은 한계

- 구간 시간과 순서는 직선 어림과 욕심 방식이다. 둘째 지점 이후의 들어오는 방향은 계획할 때 차 위치 기준이다(research R42 한계).
- 함께 모이는 곳 없이 차례 계획만 있을 때, 확정 전 태울 사람 화면에 만날 곳 안내가 없다(research R47 한계).
- 둘째 지점의 착좌 판정(누적 좌석)은 단위 테스트로만 봤다. 시연은 페이지 "탔어요"로 넘어간다.
- 3명 차례(지점 3곳)는 단위 테스트로만 봤다.
- 탄 뒤 공유를 끈 사람은 만남까지 서버 기록을 계속 묻는다(끝난 기록이라 409·404만 오고 배너는 뜨지 않는다).
